# Errors and Outcomes

> **Status: Accepted for now**
>
> These rules are the current design and may be refined. Each section states one rule and shows what it does. Function names such as `File.read` and `Json.parse` are illustrative, and function bodies are left out where they do not matter.

The goals are:

- The standard library and user programs use the same error system.
- Errors accumulate as they pass through functions.
- The compiler always knows every outcome a function can produce.

---

## 1. Error symbols mark failure

An error symbol is written with `:!` (`lang-symbols.txt`, "Symbol kinds"). A union that contains at least one error symbol is an outcome.

`?` returns the errors early, and `!` panics on them.

```
parse(text: str) -> :ok[Json] | :!syntax[int]

load(text: str) -> :ok[Json] | :!syntax[int] {
  let json = parse(text)?
  json
}
```

If `parse` produces `:ok[json]`, `?` gives the `Json`. If `parse` produces `:!syntax[line]`, `load` returns `:!syntax[line]` immediately.

Ending a function whose result contains `:ok[T]` with a plain value returns `:ok` of that value, so `load` above ends with `json` rather than `:ok[json]`.

`?` is shorthand for this match:

```
let json = parse(text) |> {
  :ok[value] => value
  :!syntax[line] => ret :!syntax[line]
}
```

`!` takes out the success the same way and panics on an error.

```
let json = parse(text)!
```

A panic prints a message to standard error naming the file and line where it happened, then ends the program with a non-zero exit status. Integer overflow and division by zero panic in the same way.

What is left after `?` or `!`:

- one tag with a payload gives the payload;
- one tag without a payload gives nothing;
- several tags give the union of those tags, which must then be matched with an arm for each one. This holds even when two tags carry the same payload type: `:created[Id]` and `:updated[Id]` are still different cases.

```
save(user: User) -> :created[Id] | :updated[Id] | :!conflict[Id]

let change = save(user)?                // change is :created[Id] | :updated[Id]
change |> {
  :created[id] => print("created {id}")
  :updated[id] => print("updated {id}")
}
```

`:ok` is the success tag by convention, and the one used for implicit wrapping. It does not make a union an outcome; only error symbols do. A union without errors that contains `:ok` is ordinary data.

```
Health = :ok | :degraded | :down        // no errors: data, no handling needed
```

`:ok` may carry no payload.

```
// a method of File, in File.brf
close(&self) -> :ok | :!ioError[str]

file.close()!
```

A union with no error symbols cannot use `?` or `!`.

```
getAgeRange(user: User) -> :adult | :senior

let range = user.getAgeRange()?   // Compiler error: there are no errors to return
```

Optional values are not outcomes. `:none` is not an error, so `?` never returns early on it, and an optional is matched like any data (section 10).

```
greet(users: Vec[User]) -> :ok[str] | :none {
  users.find((user) => user.getName() == "Bob") |> {
    :ok[user] => "Hello " + user.getName()
    :none => :none
  }
}
```

Error symbols are written with `:!` wherever they appear: in types, in `ret` and in patterns.

## 2. Errors accumulate

Given these two functions:

```
readFile(path: str) -> :ok[str] | :!notFound[str] | :!permissionDenied[str]
parse(text: str) -> :ok[Json] | :!syntax[int]
```

A function that uses `?` on both must declare the errors of both.

```
loadJson(path: str) -> :ok[Json] | :!notFound[str] | :!permissionDenied[str] | :!syntax[int] {
  let text = readFile(path)?   // may return :!notFound or :!permissionDenied
  let json = parse(text)?      // may return :!syntax
  json
}
```

The pipeline form accumulates the same way.

```
loadJson(path: str) -> :ok[Json] | :!notFound[str] | :!permissionDenied[str] | :!syntax[int] {
  path |> readFile()? |> parse()?
}
```

Leaving an error out is a compile error.

```
loadJson(path: str) -> :ok[Json] | :!syntax[int] {
  let text = readFile(path)?   // Compiler error: loadJson does not declare
                               // :!notFound[str] or :!permissionDenied[str]
  parse(text)?
}
```

The return type can also be left out, and the compiler builds the same union.

```
loadJson(path: str) {
  path |> readFile()? |> parse()?
}

// inferred: :ok[Json] | :!notFound[str] | :!permissionDenied[str] | :!syntax[int]
```

Or the success type can be written and the rest left to the compiler with `_`.

```
loadJson(path: str) -> :ok[Json] | _ {
  path |> readFile()? |> parse()?
}
```

All three forms are allowed on any function. A written type is always checked against the body.

`_` is allowed only in function return types and must accompany a written `:ok`
tag fixing the success type. It adds inferred tags to any written ones; it is
not an open union usable in type declarations, fields, parameters or local
annotations. Only reachable returns and propagation paths contribute to
inference; unreachable syntax is still checked.

## 3. Named unions

Listing every tag in a written return type gets long. A module can name its errors once. A type declaration needs no keyword.

```
// file: File.brf

Error = :!notFound[str] | :!permissionDenied[str]

pub read(path: str) -> :ok[str] | Error

// file: Json.brf

Error = :!syntax[int] | :!missingKey[str] | :!wrongType[str]

pub parse(text: str) -> :ok[Json] | Error
```

In a union, an entry that starts with `:` is one tag. An entry that is a type name includes every tag of that union.

```
// file: User.brf

pub loadUser(path: str) -> :ok[User] | File.Error | Json.Error | :!invalidAge[int] {
  let text = File.read(path)?
  let json = Json.parse(text)?
  let name = json.getStr("name")?
  let age = json.getInt("age")?

  User.new(name, age)
}
```

That return type is the same as writing:

```
:ok[User] | File.:!notFound[str] | File.:!permissionDenied[str] |
  Json.:!syntax[int] | Json.:!missingKey[str] | Json.:!wrongType[str] |
  :!invalidAge[int]
```

## 4. Tags from different modules

A tag belongs to the module it is written in (`lang-symbols.txt`, "Tags belong to modules"). Two modules can use the same tag name, even with the same payload type, and the tags stay different.

```
// File.read -> :ok[str] | File.:!notFound[str]
// Http.get -> :ok[str] | Http.:!notFound[str]

fetch(source: str) {
  let local = File.read(source)?
  Http.get(local)
}

// inferred: :ok[str] | File.:!notFound[str] | Http.:!notFound[str]
```

The caller can tell which call failed.

```
fetch("config") |> {
  :ok[text] => print(text)
  File.:!notFound[path] => print("no file {path}")
  Http.:!notFound[url] => print("no page {url}")
}
```

A merged symbol matches both with one name, and gives each payload type its own arm when they differ (`lang-symbols.txt`, "Merged symbols").

Within one module, a tag has the same payload types everywhere. No payload and a `()` payload are different: `:!missing` and `:!missing[()]` cannot both be used in one module.

```
// one module

parse(text: str) -> :ok[Json] | :!invalid[int]
validate(json: Json) -> :ok[User] | :!invalid[str]   // Compiler error: :!invalid already
                                                      // has the payload int in this module
```

The fix is to rename one of them.

```
parse(text: str) -> :ok[Json] | :!syntax[int]
validate(json: Json) -> :ok[User] | :!invalid[str]
```

## 5. Specific tags in the standard library

A generic tag tells the caller nothing.

```
open(path: str) -> :ok[File] | :!err[str]   // avoid
```

A specific tag says what happened and lets the caller choose a response.

```
// file: File.brf
pub open(path: str) -> :ok[File] | :!notFound[str] | :!permissionDenied[str]

// in another module
File.open("data.txt") |> {
  :ok[file] => print("Opened")
  File.:!notFound[path] => print("No file at " + path)
  File.:!permissionDenied[path] => print("Cannot read " + path)
}
```

## 6. Handling outcomes

An outcome can never be ignored. It is handled in one of three ways.

**Where the call is made**, with `?`, `!` or a match.

```
file.close()!               // panic on failure

file.close()?               // return the failure to the caller

file.close() |> {           // handle each outcome
  :ok => print("Closed")
  File.:!ioError[message] => print(message)
}
```

**By returning it as it is.** A call that is the function's final expression, the last expression of a branch that ends the function, or the value of `ret` counts as handled. Its errors join the function's result, as with `?`, and the outcome is returned unchanged rather than wrapped in `:ok`.

```
load(path: str) -> :ok[str] | :!notFound[str] {
  readFile(path)            // returned as it is: no ? needed
}
```

**Later, from a binding.** A binding that holds an outcome must be handled exactly once, on every path, before it goes out of scope: by a match, `?`, `!` or returning it. Until then it cannot be passed to a function, stored in a field, copied to another binding or reassigned. The check is the flow analysis that declared-then-assigned bindings already need, run the other way: instead of "assigned before every read", it is "handled before every exit". Passing a stored outcome to a function may be allowed later.

```
let result = Loan.new(0, 500, 10)
print("trying a zero balance")
result |> {                 // handled before the scope ends
  :ok[loan] => print("ok")
  problem => print("refused")
}

let other = Loan.new(1, 2, 3)
if done {
  ret                       // Compiler error: other is not handled on this path
}
```

A call that is neither handled nor bound is a compile error, in every position, including the body of a lambda.

```
file.close()                // Compiler error: the outcome is not handled
```

As a result, every point where a function can fail is visible in its body: each `?`, each returned call, and each `ret` of an error symbol.

A union without error symbols, such as `:adult | :senior`, is ordinary data. It can be stored, passed, and returned freely.

```
describe(user: User) {
  user.getAgeRange()        // allowed: returns :adult or :senior
}
```

A result that is not an outcome may be ignored.

```
print("Hello")              // allowed: print returns ()
```

## 7. Handling an error removes it

A catch-all arm receives only the tags that earlier arms did not handle.

```
loadOrEmpty(path: str) -> :ok[Json] | :!permissionDenied[str] | :!syntax[int] {
  let text = readFile(path) |> {
    :ok[text] => text
    :!notFound[missing] => "\{}"
    other => ret other
  }

  parse(text)?
}
```

`:!notFound` is handled inside the function, so it does not appear in the return type. `other` has the type `:!permissionDenied[str]`.

Without this rule a function that uses a catch-all would have to declare errors it has already dealt with.

## 8. A smaller union fits a larger one

`User.new` produces fewer tags than `fromJson` declares. That is allowed.

```
pub new(name: str, age: int) -> :ok[User] | :!invalidAge[int]

pub fromJson(json: Json) -> :ok[User] | Json.Error | :!invalidAge[int] {
  let name = json.getStr("name")?
  let age = json.getInt("age")?

  User.new(name, age)
}
```

The reverse is a compile error.

```
make() -> User {
  User.new("Bob", 20)?  // Compiler error: :!invalidAge[int] is not declared
}
```

For this to cost nothing at runtime, each tag has one number across the whole program, so a value never needs converting when it moves to a larger union.

## 9. Functions return exactly their type

A function returns its type and nothing else. `double(x: int) -> int` returns an `int`, and its result cannot be matched as `:ok[v]`.

```
double(x: int) -> int {
  x * 2
}

let y = double(3) + 1       // an int
```

A plain value is wrapped in `:ok[...]` only when the function's result is a union that contains `:ok[T]`.

A union whose only tag is `:ok[T]` is the same type as `T`, and `:ok` alone is the same as `()`. This lets a generic function return `:ok[U] | E`: when `E` is empty, the result is a plain `U`. A collection function returns `:ok[Vec[U]] | E`, where `E` is the errors of the lambda it was given.

```
users |> select((user) => user.getName())          // Vec[str]
items |> select((json) => User.fromJson(json))     // :ok[Vec[User]] | Json.Error | User.:!invalidAge[int]
```

## 10. `:none` and ending without a value

`:none` means that there is no value (`lang-symbols.txt`). A function whose result includes `:none`, because its written type says so or because some `ret :none` puts it there, returns `:none` when it ends without a value.

```
find(id: int) -> :ok[User] | :none {
  for user in users {
    if user.id == id {
      ret user
    }
  }
}                                       // ends without a value: :none
```

A function whose result includes a payload-less `:ok` returns `:ok` when it ends without a value. Other functions that end without a value return `()`.

A union with a payload-less `:ok` and `:none` together is a compile error: ending without a value would mean either.

`?` acts on errors only. It never returns early on `:none`.

Taking the value out of an optional, or leaving when there is none, is planned as `let ... else`, as in Rust. It binds the payload when there is a value and runs the block otherwise. The block must leave the scope, with `ret`, `break` or `continue`. Until it exists, a match does the same job.

```
let user = find(7) else { ret :!notFound[7] }
```

This is how a missing value becomes an error with a message: `scope.get(name) else { ret :!undefined[name] }`.

---

## 11. Named unions as patterns

A named union can be used as a pattern in a match block. It matches any tag in the union.

```
User.fromJson(json) |> {
  :ok[user] => print(user.getName())
  Json.Error => print("The JSON was not valid")    // :!syntax, :!missingKey, or :!wrongType
  User.:!invalidAge[age] => print("Age is not allowed")
}
```

Exhaustiveness still applies. Leaving out `User.:!invalidAge[age]` above is a compile error.

---

## 12. Entry results

`main()` takes no parameters. Its ordinary result is released and discarded, and
execution exits 0. This includes a union without error symbols: ending with
`classify(1)` or `:adult` does not turn ordinary data into an error.

When `main()` ends on an error symbol, it prints `error: ` and the symbol with
its payload to standard error, releases the result and exits 1. Any other
result, including `:ok`, exits 0. Prior standard output is flushed before error
or panic output. A panic does not unwind owners.

Error diagnostics quote and escape string/character payloads and show fields of
structs and nested symbols. Diagnostic formatting may abbreviate large or deeply
nested values with `...`; it is not a serialization API or a general `str` conversion.

---

## Putting it together

`loadUser` from section 3 declares seven outcomes. A caller in another module that matches on it must cover all seven.

```
User.loadUser("bob.json") |> {
  :ok[user] => print(user.getName())
  File.:!notFound[path] => print("Missing file " + path)
  File.:!permissionDenied[path] => print("Cannot read " + path)
  Json.:!syntax[line] => print("The file is not valid JSON")
  Json.:!missingKey[key] => print("Missing field " + key)
  Json.:!wrongType[key] => print("Wrong type for field " + key)
  User.:!invalidAge[age] => print("Age is not allowed")
}
```

Removing any arm is a compile error. Adding a new tag to `Json.Error` makes this match a compile error until the new tag is handled.
