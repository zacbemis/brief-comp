# Syntax

> Part of the language design. `lang-desc.txt` has the overview and the list of documents.

## Comments

```
// a comment to the end of the line

/* a comment that
   can span lines */
```

## Names

Casing is part of the grammar, and breaking it is a compile error.

- Types, modules and traits start with a capital: `Date`, `Json`, `HasUser`.
- Functions, variables, constants, fields, parameters and symbol tags start with a lowercase letter: `daysIn`, `date`, `maxUsers`, `year`, `:badYear`.
- The primitive types, such as `int` and `str`, are keywords and stay lowercase.

The first letter tells a reader, and the parser, what a name is: `Date.new()` is called on a type and `date.label()` on a value, and `Date { ... }` is a literal while `ready { ... }` is not.

```
let Count = 0              // Compiler error: a variable starts with a lowercase letter
const MAX_USERS = 100      // Compiler error: a constant starts with a lowercase letter
date {                     // Compiler error: a struct starts with a capital
  day: int
}
const maxUsers = 100       // allowed
```

## Statements and line breaks

Statements are separated by newlines. There is no statement terminator.

```
let user = User.new("Bob", 20)!
let name = user.getName()
```

Fields in a struct definition and arms in a pattern-matching block are also written one per line. Short matches cannot be put on one line.

A statement may span several lines. The examples in this document assume a newline does not end a statement when it appears:

- Inside `( )` or `[ ]`.
- After a token that cannot end a statement, such as `,`, `:`, `=`, `=>`, `->`, `|>`, `.`, or a binary operator. In a type, this includes the `|` that joins a union.
- After a keyword that still needs its declaration, condition, iterable, or body: `let`, `var`, `const`, `pub`, `import`, `if`, `else`, `for`, `in`, `while`, `and`, `or`, or `not`.
- Before a line that begins with `|>` or `.`.

```
let total = price +
  tax +
  shipping

let valid = json
  |> parse()?
  |> validate()?

let label = user
  .getName()
  .trim()

let user = User.new(
  "Bob",
  20
)!

read(path: str) -> :ok[str] | :!notFound[str] |
  :!denied[str] | :!failed[str] {
  ...
}
```

These continuation rules are accepted for now and may be refined.

## Variable declarations

The language distinguishes binding mutability from data mutability.

| Declaration | Binding | Data |
|---|---|---|
| `let` | Immutable | Mutable |
| `var` | Mutable | Mutable |
| `const` | Immutable | Immutable |

Examples:

```
let user = User.new("Bob", 20)!
var counter = 0
const maxUsers = 100
```

`let` prevents reassigning the variable, but does not inherently make the referenced object immutable.

The table describes the binding itself. A struct value read from an ordinary (non-`&`) parameter stays read-only whichever binding holds it (`lang-memory.txt`, "Mutable borrow").

`var` allows the binding to be reassigned.

`const` provides immutable data in addition to an immutable binding.

```
let user = User.new("Bob", 20)!
user = User.new("Ann", 30)!   // Compiler error: user is a let binding

var counter = 0
counter = counter + 1         // allowed
```

Names are visible after their declaration, not inside their own initializer.
An initializer can still refer to an outer binding with the same name. A name
cannot be declared twice in one lexical scope; an inner block may shadow an
outer name. Function parameters are immutable bindings, as are `for` loop
iteration bindings.

The previous `const var` combination has been removed from the current design.

### Declared, then assigned

A `let` or `var` can be declared with a type and no value, and assigned later. It must be assigned as a whole before it is read, on every path, or it is a compile error. A `let` declared this way is assigned exactly once.

```
let squares: Arr[int]                 // declared, not yet assigned
squares = Arr[int] {1, 4, 9}          // assigned before use

let label: str
if count == 1 {
  label = "one item"
} else {
  label = "{count} items"
}
print(label)                          // allowed: assigned on both paths

let total: int
print(str(total))                     // Compiler error: total is not assigned
```

### Type annotations

A binding can state its type after the name, in the same `name: type` form used for fields and parameters. The annotation is optional.

```
let count: lng = 0
var ratio: flt = 0.5
const maxUsers: int = 100
let users: Vec[User] = Vec[User]()
```

Without an annotation the type comes from the value.

```
let count = 0                     // int
let name = "Bob"                  // str
let user = User.new("Bob", 20)!   // User
```

An annotation that does not match the value is a compile error.

```
let count: int = "Bob"       // Compiler error: str is not int
```

## Operators

Arithmetic:

```
x + y
x - y
x * y
x / y
x % y     // remainder
x ** y    // power
```

Increment, decrement, and compound assignment:

```
x++
y--
x += y
x -= y
x *= y
x /= y
x %= y
```

Increment (`x++`) and decrement (`x--`) are standalone statements, not
expressions. They update a mutable numeric target by one and produce no value,
not even the old value. Their target must be a binding, field, or indexed
element, as for assignment. Prefix `++x` and `--x` are not supported.
`let old = x++`, `f(x++)`, and `while count++ < 3 { ... }` are syntax errors;
write the update as a separate statement.

Assignment (`=`) and compound assignment (`+=`, `-=`, `*=`, `/=`, `%=`) are
standalone statements, not expressions. They produce no value and do not chain.
The target must be a binding, field, or indexed element. For example, `a = b`,
`user.age += 1` and `arr.(i) = 0` are statements, but `a = b = c`,
`if a = b { }`, and `f(a = 1)` are syntax errors. Use `==` to compare values in
a condition.

Comparison:

```
x == y
x != y
x < y
x <= y
x > y
x >= y
```

Bitwise:

```
x & y     // and
x | y     // or
x ^ y     // exclusive or
~x        // not
x << y    // shift left
x >> y    // shift right
```

`|` is the bitwise or in expressions and joins a union in types. Types are only read where a type is expected, so the two do not clash.

### Logical operators

Logical operators are the keywords `and`, `or` and `not`.

```
if age >= 18 and age < 100 {
  ret true
}

if not user.isActive() or user.isBanned() {
  ret false
}
```

`&&`, `||` and a prefix `!` are not part of the language. `!` is only about failure: after a call it unwraps a success or panics, and in `:!` it marks an error symbol (`lang-symbols.txt`). A prefix `!`, as in `!user.isActive()`, is a compile error that suggests `not`.

## What each bracket and symbol means

- `()` calls a function. After a `.`, it indexes: `arr.(i)` (`lang-types.txt`, "Arrays and vectors").
- `[]` gives type arguments: `Vec[T]`, `Arr[T]`. It also holds a symbol's payload, in types and in values: `:ok[Date]`, `:!badYear[year]`.
- `{}` is a block, whose meaning depends on what it follows: a function body, a struct or trait, a match, an `if` or a loop, or a literal.
- `.` reaches into anything with members: a field (`date.year`), a method (`date.label()`), an associated function (`Date.new(...)`), an item of a module (`Json.parse(...)`) or an element (`arr.(i)`).
- `:` gives a type (`year: int`), lists the traits a struct conforms to (`Admin: Printable`) or starts a neutral symbol (`:more`). It is not used for values.
- `:!` starts an error symbol (`:!badYear`).
- `->` gives a function's return type.
- `|` joins symbols into a union, in types (`:ok[Date] | DateError`).
- `=` gives a value, including struct fields in a literal: `Date { year = year, month = month, day = day }`. In a type declaration it gives a type: `DateError = ...`.

## Operator precedence

Operators earlier in this list bind tighter than operators after them.

1. Postfix: `f()` `x.y` `x.(i)` `?` `!`
2. Power: `**`
3. Prefix: `-x` `not x` `~x`
4. `*` `/` `%`
5. `+` `-`
6. `<<` `>>`
7. `&`
8. `^`
9. `|`
10. Range: `..` `..=`
11. Pipeline: `|>`
12. Comparison: `==` `!=` `<` `<=` `>` `>=`
13. `and`
14. `or`

Operators on the same level group left to right. `**` groups right to left. Ranges and the comparison operators do not chain. Assignment, increment, and decrement are statement-only, so they have no expression precedence.

`not` binds as tightly as the other prefix operators, so `not a == b` is `(not a) == b`. Write `a != b`, or `not (a == b)`.

### Arithmetic

```
a + b * c          // a + (b * c)
a - b - c          // (a - b) - c
2 ** 3 ** 2        // 2 ** (3 ** 2)
-2 ** 2            // -(2 ** 2)
not user.isActive() // not (user.isActive())
```

### Bitwise operators and comparisons

Bitwise operators bind tighter than comparisons, so a mask test needs no parentheses.

```
flags & mask == 0     // (flags & mask) == 0
a | b ^ c & d         // a | (b ^ (c & d))
```

### Comparisons do not chain

```
a < b < c             // Compiler error
a < b and b < c       // write this instead
```

### Ranges

`..` and `..=` bind looser than arithmetic and tighter than `|>` and comparisons.

```
0..count + 1          // 0..(count + 1)
0..10 |> sum()        // (0..10) |> sum()
```

### Pipelines

`|>` binds tighter than comparisons and logical operators, so a pipeline can be compared or combined directly.

```
count |> double() > 10         // (count |> double()) > 10
a |> f() and b |> g()          // (a |> f()) and (b |> g())
x + 1 |> double()              // (x + 1) |> double()
```

Two cases need parentheses.

Matching on a comparison:

```
age >= 18 |> {                 // read as age >= (18 |> { ... })
  true => "Adult"
  false => "Minor"
}

(age >= 18) |> {               // write this instead
  true => "Adult"
  false => "Minor"
}
```

Arithmetic on the result of a pipeline:

```
x |> double() + 1              // read as x |> (double() + 1): Compiler error
(x |> double()) + 1            // write this instead
```

### Logical operators and binding initializers

```
a or b and c                   // a or (b and c)
let ok = age >= 18 and hasId   // let ok = ((age >= 18) and hasId)
```

## Control flow

### `if`

```
if age < 18 {
  print("Minor")
} else if age < 100 {
  print("Adult")
} else {
  print("Senior")
}
```

`if` produces a value, so it can be assigned. Each branch's last expression is that branch's value.
When the value is used, branches that reach their end must have compatible
types. When it is discarded, including at the tail of a `-> ()` function,
branch values are ignored individually.

```
let label = if age < 18 {
  "Minor"
} else {
  "Adult"
}

let label = if age < 18 { "Minor" } else { "Adult" }
```

An `if` without an `else` produces nothing (`()`), so its result cannot be assigned.

```
let label = if age < 18 { "Minor" }   // Compiler error: there is no value when age >= 18
```

A match block produces a value in the same way (`lang-pipelines.txt`).

### `while`

```
var count = 0

while count < 10 {
  count += 1
}
```

### `for`

`for` walks a range or a collection.

```
for i in 0..10 {
  print(str(i))     // 0 through 9
}

for i in 1..=10 {
  print(str(i))     // 1 through 10
}

for user in users {
  print(user.getName())
}
```

A range `a..b` includes `a` and excludes `b`; `a..=b` includes both. Its bounds
are integers of the same type and are evaluated once, left to right, before the
loop starts. It walks upward by one; when `a >= b` (for `..=`, when `a > b`),
the body does not run. The iteration binding is immutable and is visible only
in the loop body. `continue` advances to the next value before testing the
bound again.

The iteration binding takes the type of the bounds. When both bounds are
literals, they are `int` unless the binding is given a type:

```
for n: lng in 2..10000 {
  ...
}
```

Over an array or vector, `for x in arr` gives the elements, and `for i in 0..arr.len()` gives the indices.

`while` and `for` are statements producing `()`, not value-producing
expressions; their results cannot be assigned or passed as arguments.

### `break` and `continue`

`break` leaves the nearest enclosing loop. `continue` skips to its next iteration.

```
for user in users {
  if user.getAge() < 18 {
    continue        // skip minors
  }

  if user.getName() == "Bob" {
    print("Found Bob")
    break           // stop looking
  }
}
```

Both are only allowed inside a loop.

```
main() {
  break             // Compiler error: not inside a loop
}
```

In nested loops they apply to the innermost one. There are no loop labels.

```
for row in rows {
  for cell in row {
    if cell == 0 {
      break         // leaves the inner loop only
    }
  }
}
```

## Literals and blocks

A bare `{ ... }` is not a general expression or a standalone statement.
Blocks must be introduced by a function header, a struct or trait name,
`if`/`else`, `while`, `for`, a match arm's `=>`, or `|>`. For example,
`print({ ... })` is a syntax error. An `if` or pipeline match can still produce
a value as described above.

`Name { ... }` defines a struct or trait where a declaration is expected and creates a value where an expression is expected. A literal of an array or vector also ends in braces: `Arr[int] {1, 2, 3}`, `Vec[str] {"a", "b"}`.

After `if`, `for`, and `while`, the first `{` always starts the body.

```
for user in users {
  print(user.getName())
}
```

A literal that ends in `{ ... }` in a condition or iterable must be wrapped in `( )` or appear inside a call's arguments. The compiler's error says what to wrap.

```
if Guest { name = name }.isAllowed() {     // Compiler error: the first { starts the body
}

if (Guest { name = name }).isAllowed() {   // allowed: wrapped in ( )
}

if isAllowed(Guest { name = name }) {      // allowed: inside call arguments
}

for x in (Arr[int] {1, 2, 3}) {            // allowed: wrapped in ( )
}
```

The same rule applies to any future keyword that is followed by an expression and then a block.

## Type arguments in expressions

Type arguments are written in square brackets, in types and in expressions. Square brackets are never used for indexing, so `Vec[User]()` cannot be confused with an index or a comparison.

```
let users = Vec[User]()         // an empty vector of User
let grid = Vec[Vec[int]]()      // a vector of vectors
let smaller = a < b             // always a comparison
let first = users.(0)           // indexing uses .( )
```

A generic function called with explicit type arguments writes them the same way: `parse[int](text)`. `lang-traits.txt` describes generics.
