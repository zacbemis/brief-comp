# Plan: The First Version of the Compiler

> **Status: Milestones 0–5 implemented for the first-version scope; milestone 6 in progress.** This describes how the first version of the compiler will be built. The language it accepts is listed under "First version" in `docs/lang-desc.txt`. The language rules themselves are in the other `docs/lang-*.txt` files.

## Goal

A compiler, written in C, that reads one `.brf` file and produces a native program by emitting C and running an existing C compiler on it.

```
brief run hello.brf          // compile and run
brief build hello.brf -o hello
brief emit-c hello.brf       // print the generated C
```

The first version is done when every example in the docs that falls inside its scope compiles and behaves as described, and every compile error described in the docs is reported for the matching example.

## Principles

- **A working program end to end as early as possible.** The second milestone already turns `main() { print("Hello") }` into a running program. Every later feature is added through every stage at once, so the whole pipeline is always testable.
- **One stage per job.** Each stage reads the previous stage's output and can be tested on its own.
- **Report many errors at once.** Stages collect diagnostics and keep going where they can, instead of stopping at the first error.
- **Simple memory inside the compiler.** The compiler is a short-lived process, so everything it builds is allocated from arenas and freed together at exit.
- **The generated C is plain and readable.** It is meant to be read when debugging, and it is what the bootstrapped compiler will also produce.

## Pipeline

```
.brf source
  -> Lexer             tokens
  -> Newline filter    tokens, with newlines that do not end a statement removed
  -> Parser            syntax tree
  -> Name resolution   every name linked to what it refers to
  -> Type checking     every expression typed, symbol sets inferred, matches checked
  -> Lowering          a small statement-based form with explicit temporaries
  -> Reference counts  increments and decrements inserted
  -> C emission        one C file, with the runtime included
  -> cc                native program
```

### Source files and diagnostics (`src/common`)

- **`SourceFile`**: the path, the text, and the byte offset where each line starts, so any offset can be turned into a line and column.
- **`Span`**: a file and a start and end offset. Every token and every syntax tree node carries one.
- **Diagnostics**: each error has a span, a message, and optional notes. They are printed with the source line and a marker under the problem, in the style Elm made popular:

  ```
  error: loadJson does not handle the errors parse can return
    --> users.brf:12:22
     |
  12 |   path |> readFile()? |> parse()
     |                          ^^^^^^^ add ? to return them, ! to panic, or match them with |> { ... }
  ```

- **Arena allocator**: one arena for the whole compilation. Syntax tree nodes, types, and strings are allocated from it and never freed individually.
- **String interning**: the parser interns identifier spellings; semantic analysis canonicalizes symbol tags. Current name-table lookups may still compare bytes; canonical type/tag identity is shared.

### Lexer (`src/lexer`, exists)

The lexer covers the documented tokens. Groundwork changes implemented in milestone 0:

- **Unterminated block comment.** `/* ...` running to the end of the file is an error at the opening delimiter.
- **Escapes.** String and character escapes are checked against the documented list. An unknown escape is an error, and a character literal must contain exactly one decoded byte. Both kinds of literal must close on the same source line; an unterminated literal leaves the newline available for recovery.
- **Positions.** Each token carries a source span; error messages are separate from source spelling. Multiline tokens point at their starting line.
- **Whole file at once.** The lexer can collect all tokens, including errors and EOF, into an arena array. The parser will use it to look ahead and back up for generic calls (see Parser).
- **Raw newlines.** Newlines inside block comments are preserved so comments cannot accidentally join statements. The newline filter removes continuation newlines before parsing.

### Newline filter (`src/lexer`)

Newlines end statements except in the cases listed in `lang-syntax.txt`. A small layer between the lexer and the parser removes the newlines that do not end a statement.

- **Brackets.** It keeps a stack of open brackets. When the innermost open bracket is `(` or `[`, newlines are removed. When it is `{`, they are kept. This matters because a match block inside call arguments still needs newlines between its arms:

  ```
  items |> select((json) => User.fromJson(json) |> {
    :ok(user) => user                  // newlines inside { } still separate arms
    Json.Error => User.blank()
  })
  ```

- **Continuation tokens.** A newline after a token that cannot end a statement (`,` `:` `=` `=>` `|>` `.` or a binary operator) is removed.
- **Continuation lines.** A newline before a line that starts with `|>` or `.` is removed.

- **Type argument closers.** A `>` or `>>` closing type arguments in a type annotation, a named type, or `Sym` is not a binary continuation operator. The filter records these lexical contexts so field and declaration separators are preserved. Generic-call disambiguation still belongs to the parser.

Doing continuation filtering in one place keeps expression parsing free of continuation-newline special cases. The parser consumes retained separators and allows retained newlines before `else`.

### Parser (`src/parser`)

Recursive descent for declarations, statements, and patterns. Expressions use a Pratt parser driven by a table built from the precedence list in `lang-syntax.txt`. Each operator gets a binding power, and the two operators that do not chain, comparisons and `..`, are rejected when chained.

Cases that need specific handling:

| Case | Approach |
|---|---|
| `Vec<User>()` versus `a < b` | After a name and `<`, try to parse type arguments. If they close with `>` and `(` follows, keep the generic call. Otherwise rewind to the saved token position and parse a comparison. |
| `>>` closing two type argument lists | When a type argument list expects `>` and finds `>>`, split the token in two. |
| Struct literal after `if`, `for`, `while` | A parser flag forbids struct literals until the next `(`, `[`, or call argument list, as Rust does. |
| `x?`, `x!`, and `x != y` | The lexer already makes `!=` one token, so a `!` after an expression is always the postfix panic. |
| Pipeline stages | After the pipeline operator, a `{` starts a match block. Otherwise the stage must be a call whose callee is a name or dotted path; calls through a call result or indexed value are rejected. |
| Assignment and updates | Assignment and compound assignment are standalone, non-chaining statements. `x++` and `x--` are also standalone, valueless statements. None are Pratt expression operators, and all are rejected in conditions, arguments, and other value contexts. |
| Patterns | The parser accepts literals, `_`, binding names, tags/payload patterns, named sets, ranges and comparisons. First-version checking supports only a binding or `_` as a symbol payload pattern; refutable/nested payload patterns remain deferred. |
| `if` as a value | `if` is parsed as an expression everywhere. Type checking decides whether its value may be used. |

**Error recovery.** After an error, skip to the next newline or `}` at the current nesting level and continue, so one mistake does not hide the rest. `dump-ast` runs parsing even when lexing reports errors; an error token is not diagnosed again as a syntax error.

**Syntax tree.** Each node is a struct with a kind, a span, and a union of kind-specific fields, allocated from the arena. Lists are arena arrays with a count. The existing kind enums in `include/ast` become the tags of these unions.

**Debugging aid.** `brief dump-ast file.brf` prints the tree as nested parentheses. Parser tests compare this text. The command reports syntax errors but does not resolve names or perform semantic checks.

**Implementation limits.** Parser recursion and expression/type tree depth are limited to 128 levels, with a diagnostic when exceeded. The tree-depth check also covers long left-associated operator chains and repeated array type suffixes, which do not recurse while being parsed.

### Name resolution (`src/sema`)

- Collect the file's structs, named symbol-set aliases and functions before resolving bodies. Reject duplicate/reserved names. `const` declarations can parse but remain unsupported, rather than becoming first-version constants.
- Attach each `impl` block's functions to its struct.
- Walk each function with nested scopes, linking every name to a parameter, local, function, struct, named type, or constant.
- Check that `main()` exists.
- Calls written `x.f()` and `x |> f()` depend on the type of `x`, so they are resolved during type checking.

### Type checking (`src/sema`)

This is the largest stage.

**Types** are created once and shared, so two types are equal exactly when their pointers are equal. They are:

- The primitives.
- Structs.
- `()`.
- Symbol sets.

A symbol set is a sorted list of tags, each with an optional payload type. Every tag name gets one number for the whole program, as `lang-errors.txt` requires.

**Checking in two directions.** Every expression is either checked against a type the context expects, or its type is worked out from the expression alone. This is bidirectional type checking. It is what lets number literals take their type from context, and later lets lambda parameters take their types from the function they are passed to.

**Return type inference.**

1. Build the call graph between functions and split it into groups that call each other (strongly connected components, found with Tarjan's algorithm using explicit work stacks rather than C recursion). Long valid call chains must not consume the compiler's stack.
2. Check groups in dependency order, so a function's callees are known before its body is checked.
3. Inside a group of mutually recursive functions, re-check until types stabilize. M3 implements plain primitive returns, extended to nominal structs in M4, with the finite lattice unknown → concrete type → error. Non-literal anchors propagate before decimal defaults, then whole-number defaults, so numeric literals do not prematurely fix recursive results to `int`. M5's data-symbol slice extends this to growing unions of tags with exact payload types; contradictory payload types still reach error. The outcome slice uses the same monotone union fixpoint for reachable propagated errors and partial annotations, with a fixed compatible success payload; sets only grow and the number of tags is finite. Success-only full outcomes erase to plain-value ABIs.
4. A function whose success type can only come from itself, such as `f() { f() }`, is reported as needing a written return type.

**The error rules** from `lang-errors.txt`:

| Rule | How it is checked |
|---|---|
| A call that can fail is handled where it is made | When a call's full outcome has both `:ok` and other variants, its parent must be `?`, `!`, or a pipeline into a match block (ignoring parser parentheses and synthetic pipeline owners). Data-only symbol results without `:ok` are ordinary values. Anything else is an error. |
| Errors accumulate | A function's set is the union of every `?`, every `ret` of a symbol, and its final value. |
| Ending with a plain value returns `:ok` of it | The final value is wrapped when the function's set has other variants. |
| A result that can only be `:ok` is used directly | Its type is treated as the payload type wherever a value is expected. |
| Same tag, different payload | Reported when two sets are combined. |
| Written return types | The inferred set must fit inside the written one. `_` lets the rest be inferred. |

**Exhaustiveness.** The first-version checker and lowering share normalized coverage metadata, not a general nested-pattern decision tree:

- Numeric/bool/byte-character patterns use inclusive `uint64_t` ranks and interval coverage/usefulness. A half-open integer range `18..100` covers 18 through 99. Floating ranks preserve signed-zero equality; a catch-all is required for NaN.
- Symbol arms use finite tag sets, exact payload types and residual/group coverage. Payload patterns are limited to bindings and `_`.
- String literals use complete decoded bytes and a coverage hash table; a catch-all is required for the unbounded string domain.
- Lowering emits ordered branch tests from these records, with the same useful arms and normalized bounds. Missing coverage and unreachable arms are errors even when a match result is discarded.

Diagnostics currently report nonexhaustiveness without an example witness. The general nested symbol/payload decision tree and witness generation remain future work; the Jacobs/Maranget resources below are design references, not claims that their complete algorithms are implemented.

**Other checks:**

- `let` bindings are not reassigned.
- Fields are only assigned through writable access. Direct aliases of ordinary parameters stay read-only, even in local `let`/`var` bindings. A separate intraprocedural permission pass propagates access through assignments, branches and loop fixpoints after types stabilize. A struct call result is read-only when some struct type is reachable through fields from both its type and a read-only argument's type, and a struct literal is read-only when built from a read-only struct. A read-only struct cannot be stored in a field, so a function that keeps an argument takes it as `&`. This is not a purity guarantee.
- `break` and `continue` appear only inside loops.
- An `if` without `else` is not used as a value.

Privacy is per module, and this version has one module per program, so privacy checks arrive with modules.

### Lowering (`src/ir`)

C expressions cannot contain statements, but here `if`, match blocks, and `?` produce values. Lowering turns the checked tree into a small statement-based form:

- Every intermediate value gets a named temporary.
- `if` and match blocks that produce values write to a temporary declared before them.
- `?` becomes a test of the tag followed by an early return.
- Each early return is explicit, so the next step can see every place a function can exit.

This form is what Koka and Lean insert reference counts into, and it keeps C emission a direct printing step.

### Reference counts (`src/ir`)

The rules, following Lean's borrowed parameters and Lobster's ownership analysis:

- **Locals own** what they hold. A struct or string is released when the last owner goes out of scope, and at every early return.
- **Parameters borrow.** The caller keeps the value alive. M4 conservatively pins reference reads into owned temporaries, including all reference arguments; eliminating provably unnecessary counts is a later optimization.
- **Returned values are owned** by the caller.
- **Storing** a value in a field or another local adds a reference. **Overwriting** a field or a `var` releases the old value.
- **String literals** are marked as permanent and are never counted.

**The one unsafe case is guarded.** A borrowed parameter could be freed during the call if the same call also passes a `&` parameter that can overwrite where it came from:

```
setChild(user.child, user)    // setChild(child: Child, user: &User) could replace user.child
```

M4 pins every reference-valued read, not just field arguments in calls with `&` parameters. This also protects a first argument from a mutation performed while evaluating a later argument. Parameters themselves borrow; returns transfer an owned reference; stores retain before releasing their old values. Lowering records lexical/exit drops, and the separate, idempotent `ir_insert_rc()` pass inserts counts and releases reused temporary slots. Emission requires this pass.

Cycles are not collected in this version. Debug builds can print the objects still alive at exit, as Lobster does. That makes leaks from cycles visible.

### C emission (`src/codegen`)

| Language | C |
|---|---|
| `int`, `lng`, `shrt` and their unsigned forms | `int32_t`, `int64_t`, `int16_t`, `uint32_t`, `uint64_t`, `uint16_t` |
| `flt`, `dub`, `bool`, `chr` | `float`, `double`, `_Bool`, `uint8_t` |
| `str` | a pointer to the runtime's string object |
| A struct | a pointer to a C struct whose first member is the runtime's object header |
| A symbol set | a C struct with a `uint32_t` tag and a union of payloads |
| A set with only `:ok(x)` | the C type of `x` |
| `()` and `Sym<:ok>` | `void` |

- **Names** are prefixed to avoid clashes with C: `main` becomes `brf_main`, and `User.new` becomes `brm_4_User_new`. Methods encode the owner's name length and use a distinct namespace, avoiding clashes with top-level names and underscore-separated paths. Struct types use `brs_`; runtime helpers and generated temporaries use `brt_`.
- **String literals** are emitted as readable escaped C strings with explicit byte lengths. Fixed-width octal escapes preserve zero/non-ASCII bytes without absorbing following digits; question marks are escaped to prevent C11 trigraphs.
- **Sets of different sizes.** Global tag IDs are preserved, but values with different set representations are explicitly repacked into the destination payload union. Widening does not renumber tags; zero-cost widening is not yet implemented.
- **Overflow** is checked with portable C11 range preconditions before evaluating signed arithmetic. Unsigned operations also check their language-width limits. Power and left shift use checked multiplication/doubling; division guards the signed-minimum / -1 case, while the corresponding remainder is safely zero. Each checked IR operation records its Brief file/line for panic reporting. No overflow built-ins are required.
- **Division** checks for zero before dividing.
- **`#line` directives** map the generated C back to `.brf` lines, so a debugger and C compiler warnings point at the original source. Nim does the same.
- **The entry point.** C's `main` calls the program's zero-argument `main()`, discards an ordinary result (including data-only symbols without `:ok`), and exits 0 after flushing stdout. Only outcomes with both `:ok` and other variants can fail: an active error prints `error: :tag(payload)` to standard error after flushing prior stdout, releases its owned payload and exits 1.

The generated file is plain C11 and links system `libm` for floating-point power. It builds with recent GCC or Clang on POSIX hosts with fixed-width integers and IEEE binary32/binary64 floating-point types (checked by static assertions).

### Runtime (`runtime/`)

A small C library included in every generated program:

- **Objects.** An object header holding the reference count and a pointer to a release function that releases the object's fields.
- **Memory.** Allocation that aborts on out-of-memory, plus the add-reference and release operations. Counts are not atomic, since programs are single-threaded.
- **Strings.** Creation, concatenation, comparison, and printing.
- **Builtins.** `print` and the converters: `str(...)` for numbers and `bool`, and the eight numeric-target converters for numbers, byte `chr` and `str`, returning their plain successes or full outcomes according to source-domain compatibility.
- **Panics.** Print a message with the file and line, then exit with a non-zero status.

The compiler build embeds the runtime's text in the compiler binary, so `brief` can paste it into each generated file. The output is then a single self-contained C file.

### Driver (`src/main.c`, `src/driver/`)

- `src/main.c` parses command-line arguments and coordinates compilation; `src/driver/` handles native compiler/program processes, signals, and temporary files.
- `brief run`, `brief build -o`, `brief emit-c`, and `brief dump-ast`.
- It calls the C compiler named by the `CC` environment variable, defaulting to `cc`, with `-std=c11 -O2`. A `--debug` flag switches to `-O0 -g` and turns on the sanitizers.

## Testing

**Unit tests** use the existing harness in `tests/`, extended to the newline filter, the parser (comparing `dump-ast` output), and type checking.

**Program tests** are `.brf` files in `tests/programs/`, each describing its own expected result in comments. The format is borrowed from Crafting Interpreters' test suite:

```
main() {
  print(str(1 + 2))      // expect: 3
  print("done")          // expect: done
}
```

```
main() {
  let x = 1
  x = 2                  // error: x is a let binding and cannot be reassigned
}
```

```
main() {
  var count: shrt = 32767
  count += 1             // panic: shrt overflow
}
```

A runner program in C compiles each file, runs it, and compares standard output, compile errors, panics, and the exit status (`// exit: 1`) with the comments. CTest runs it alongside the unit tests.

**Memory checks.** With `BRIEF_ENABLE_SANITIZERS` enabled on GCC/Clang, program tests also run compiled with `-fsanitize=address,undefined`. AddressSanitizer reports objects used after being freed, which catches a missing reference. Its leak checker reports objects never freed, which catches an extra reference. Together they test the reference-count rules on every program.

**The docs as tests.** Chapter-specific CMake manifests extract examples directly from `lang-*.txt`, guard adapters/counts and classify every fenced/raw fragment. Explicit scaffolding supplies omitted first-version contexts; prose scenarios, partial coverage and deferred features are distinguished from original executable examples. Generated fixtures stay separate from checked-in programs.

## Milestones

Each milestone ends with every test passing.

The following milestone paragraphs record the staged implementation history. Earlier limitations are superseded by later milestones; the README describes the cumulative implementation. The final-review checkpoint is recorded in `tests/first-version-review.md` and does not mark M6 complete.

Milestone 0 is complete: the common infrastructure, lexer fixes, warning flags, and debug sanitizers are implemented and tested. `brief dump-tokens file.brf` exercises source loading and reports all lexer errors with line, byte column, source line, and marker. This debugging command does not parse or compile programs. Unit and CLI integration tests run through CTest.

Milestone 1 is complete: the newline filter, arena-owned syntax trees, parser, recovery, and `dump-ast` are implemented. Unit tests compare tree dumps and cover precedence, generic-call rewind and virtual `>>` splitting, struct-literal ambiguity, match patterns, continuation rules, and recovery. CTest currently parses 146 examples read directly from the design docs, with small wrappers for statement, type, and pattern fragments. The main continuation example keeps its first-version syntax by replacing just its lambda-bearing call with an ordinary method call. Expected semantic errors still parse; expected syntax errors are rejected. Blocks containing later-version syntax, incomplete signatures, or multi-file API notation are excluded by the documented test manifest; their first-version grammar is covered by the focused unit tests.

Milestone 2 is complete: `run`, `build`, and `emit-c` connect minimal resolution and checking, a statement-based IR, self-contained C emission, an embedded runtime, and a POSIX native driver. The supported subset is zero-argument, non-recursive unit-returning functions, string literals, `print(str)`, function bodies, `()`, and unit returns. Bare blocks are not expressions or standalone statements; parser blocks remain available in their documented control-flow and match positions. Forward calls work; explicit `: ()` drops a final value. Other features are diagnosed as unimplemented instead of being silently ignored. The function call-graph walk limits its recursive descent to 128 function levels; full return inference and recursive groups remain milestone 3 work.

Milestone 3 is complete: all numeric primitives, contextual literals, bool/chr, lexical `let`/`var`, assignments and standalone valueless updates, checked arithmetic/bitwise operations, short-circuit logic, value-producing branches, while/range loops, and loop control run through every stage. Typed parameters and written/inferred primitive returns support forward and recursive calls. Iterative Tarjan analysis replaces the M2 call-depth limit; recursive groups need an independent return-type anchor or an annotation. Flow checking includes reachable explicit returns and fallthrough tails, still diagnoses unreachable syntax, and lets written `()` discard a tail without accepting an explicit non-unit return. Permanent strings can be bound, passed, and returned; heap strings and conversions remain M4 work.

Milestone 4 is complete: immutable heap strings support concatenation, bytewise comparisons and `str(number/bool)` with documented compact round-tripping float formatting. Nominal structs support complete named initialization in source order, field access/mutation, `impl`, associated/receiver calls, `Self`, and struct return inference. Mutation permissions follow access paths: ordinary struct parameters and their direct aliases are read-only, while `&` parameters permit writes. Struct call results are read-only when their type can reach a read-only argument's objects, literals are read-only when built from a read-only struct, and a read-only struct cannot be stored in a field. Parameter bindings cannot be replaced. A flow-sensitive permission pass handles copies, rebinding, branch joins and loop backedges/exits; loop headers grow to a function-wide fixpoint without recursively multiplying nested-loop walks. This does not provide purity or transitive `const`. Nonrecursive structs have fieldwise equality. A separate ownership pass implements borrowed parameters, owned results, pinned reference snapshots, retain-before-release stores, scope/return/loop-control cleanup and bounded reused loop slots. All compiler metadata remains arena-owned. The runtime has permanent literals, single-threaded ARC, allocation/size checks and a debug live-object report. Cycles, cloning, identity comparison, numeric-target conversions, and the other explicitly excluded features remain unimplemented; symbols and fallible conversions are M5 work.

Milestone 5 is complete for the first-version scope, implemented in reviewable slices. Its first slice implements ordinary pipeline calls and exhaustive scalar match blocks end to end. Hidden lexical owners sequence and pin pipeline inputs before the callee and later arguments, while preserving contextual numeric argument types and read-only permissions. Unqualified calls prefer receiver methods, then module functions. `src/sema/match.c` normalizes literal/range/comparison patterns to inclusive ordered ranks, checks coverage and arm usefulness without signed overflow, and supplies the same normalized intervals to lowering's ordered branch chain. All integer widths, bool, chr and IEEE floats are covered; name/wildcard arms handle any current type. IEEE comparisons cannot match NaN, so float matches require a catch-all; signed zeroes match identically. Match arms have independent immutable bindings, produce values or perform statements, and preserve scope/jump ownership and permission joins. The next slice adds data symbols without `:ok`: arena-owned canonical sets sorted by global tag ID, optional typed payloads, transparent forward named-set aliases and composition, exact-payload collision checking, and subset compatibility for bindings/fields/arguments/returns. Symbol return sets grow monotonically through SCC inference. Alias dependency walks use explicit stacks; recursive value types need struct indirection. Symbol matching supports tag arms with immutable payload bindings or wildcards, named groups and narrowed catch-alls; a separate finite-tag coverage analysis supplies the exact useful cases to lowering. Symbol sets use value-represented C tag/union structs, repacking payloads across sets without renumbering tags. This is an implementation gap from section 8's zero-cost widening goal: canonical global tags do not yet eliminate union repacking. Canonical sets are sorted independently of listing order; this does not implement the language's listing-order comparison, which remains deferred. ARC retains/releases the active payload, including nested symbols, and preserves scope/return/jump cleanup, argument pinning and loop-slot reuse. Read-only reachability includes payloads, with `&` symbol parameters granting mutation access to reachable objects. All variants are considered, conservatively restricting a result even when its active tag cannot hold an object. Bottom-up equality eligibility includes structs and symbols and excludes recursive shapes; equality never shortcuts shared identity. The outcome slice implements `:ok`, implicit success wrapping/projection, `?` propagation, `!` panics, accumulated recursive error sets, return-only partial annotations, the handled-call rule and symbol-valued entry points. Full semantic outcomes are separate from erased ABI returns, so success-only functions still return plain values; full symbols are materialized for matching/handlers. `?` narrows to the failure set before converting to the enclosing function's outcome, retaining the active payload while releasing lexical owners on its early return. Permissions follow success projections and handlers without upgrading read-only payloads. Only entry outcomes with both `:ok` and other variants are fallible: active errors print quoted/escaped payloads, release owners and exit 1. Ordinary results, including data-only symbols without `:ok`, are dropped with exit 0. Diagnostic struct/symbol traversal is limited to depth 32 and a shared budget of 1,024 nodes/fields, abbreviating with `...` rather than expanding shared graphs exponentially. These are implementation limits, not a serialization format. Both entry errors and panic headers flush earlier stdout first, including merged stdout/stderr files. Panic preserves its Brief location and does not unwind. The conversion slice adds every numeric source/target pair and decimal string parsing for all eight numeric targets. Source/target types decide whether a call has a plain success ABI or needs handling; numeric failures use payload-free `:overflow`, while malformed/out-of-range text uses `:invalid(original)` with an independently owned reference to the original string. Integer targets require exact integral values; floating targets round to nearest (ties to even), including subnormal/zero underflow. All integer-to-floating conversions have plain success ABIs; only `dub` to `flt` can fail on finite overflow. Direct numeric literals receive the target's context in ordinary and pipeline calls without retyping existing values or computed expressions. Decimal floating text rounds directly with `strtof`/`strtod`, allowing finite underflow. Full-input ASCII grammar rejects whitespace, hex, separators and embedded NULs; optional signs, decimal points/exponents and lowercase inf/nan follow `lang-types.txt`. Runtime integer bounds and half-open floating bounds guard casts before they execute. Before a narrowing float cast, finite values outside the C target range are handled explicitly: the small interval that rounds to FLT_MAX is clamped, while the overflow tie and larger magnitudes fail. No float-to-integer round trips are used to test floating conversions. A separate IR conversion operation borrows its error payload; ownership insertion drops reused results and retains the active payload independently. The string-pattern slice adds byte-exact literal matching, duplicate/usefulness checks and required catch-alls for the unbounded string domain. Resolution decodes literal bytes once; coverage borrows those bytes in an arena-owned hash table rather than copying strings on each inference probe. Lowering reuses the same decoded bytes and emits ordered string-equality tests, with immortal pattern owners in the match scope for ordinary exit/jump cleanup. Refutable/nested payload patterns and symbol ordering remain deferred features outside the milestone's first-version acceptance scope. The general nested symbol/payload decision tree remains future work rather than being approximated by scalar intervals.

The native driver invokes `CC` (default `cc`) as a single executable, never through a shell. M3 links `-lm` for floating-point power. `build` defaults to `a.out`, stages compilation beside the destination, and publishes it atomically on success. `run` uses `TMPDIR` and propagates the child's exit status. The driver ignores SIGINT while waiting and cleaning up, but restores the original disposition/mask in children, so terminal Ctrl-C stops the program without leaving temporary files. `--debug` enables native ASan/UBSan with `-O0 -g` and `BRT_DEBUG` live-object reporting. The runtime text is embedded at compiler build time, so generated C and the compiler binary do not depend on the checkout at runtime.

The C program runner is registered with CTest for normal and sanitized builds, with no interpreter dependency. Its shared POSIX process helper captures stdout and stderr as bytes, enforces 30-second compilation and 10-second execution timeouts, and kills the process group on timeout. It checks output bytes, compile diagnostic messages and source lines, panic messages, and exit statuses from fixture comments. M2 added 18 program fixtures plus stage-level and native-driver integration tests. M3 brings the fixture count to 40, including arithmetic panics, direct-precision floating-literal rounding, statement-only updates, independent inference errors, and numeric/control-flow/recursive programs. ## Risks

| Risk | Plan |
|---|---|
| Reference counting bugs are easy to make and hard to see. | Sanitizer runs on every program test from milestone 4 onward, and the conservative rule for borrowed arguments. |
| Inference across recursive functions. | The fixpoint on error sets, with an error when a success type can only come from itself. |
| The newline rules have edge cases nobody has met yet. | Keep them all in the newline filter, and add a test for every case found. |
| Generic-call detection backs up the parser. | Back-up is cheap because tokens are already in an array. Only names followed by `<` trigger it. |
| Numeric backend assumptions differ across hosts. | Fixed-width C integers, binary32/binary64 assertions, portable precondition-based overflow checks, and GCC/Clang sanitizer runs. |

## Resources

What each resource is useful for, and whether its code may be reused.

### Building a compiler in C

- **[Crafting Interpreters](https://craftinginterpreters.com)**, Robert Nystrom.
  - The existing lexer already follows the style of its C interpreter, clox.
  - Its chapter on compiling expressions is a clear Pratt parser in C.
  - Its test suite's `// expect:` comments are the model for the program tests.
  - The code is MIT licensed and the book text is CC BY-NC-ND ([license](https://github.com/munificent/craftinginterpreters/blob/master/LICENSE)).
- **[chibicc](https://github.com/rui314/chibicc)**, Rui Ueyama.
  - A small C11 compiler written in C: a tokenizer, a recursive descent parser, type assignment, and code generation.
  - Its history adds one feature per commit, which makes it a good model for how to grow a compiler in small steps.
  - MIT licensed.
- **[Writing a C Compiler](https://norasandler.com/book/)**, Nora Sandler (No Starch Press, 2024). It builds a compiler stage by stage with a test suite at each step. Its algorithms are pseudocode, so it gives structure rather than code.

### Parsing

- **[Simple but Powerful Pratt Parsing](https://matklad.github.io/2020/04/13/simple-but-powerful-pratt-parsing.html)**, Alex Kladov. Binding powers, prefix and postfix operators, and how to handle operators that do not chain.
- **[Pratt Parsers: Expression Parsing Made Easy](https://journal.stuffwithstuff.com/2011/03/19/pratt-parsers-expression-parsing-made-easy/)**, Robert Nystrom.

### Type checking

- **[Bidirectional Typing](https://arxiv.org/abs/1908.05839)**, Jana Dunfield and Neel Krishnaswami (ACM Computing Surveys, 2021). A survey of checking against an expected type versus working a type out. Its point that this gives errors at the right place is why it suits this language.
- **[Zig's inferred error sets](https://ziglang.org/documentation/master/#Inferred-Error-Sets)** and **[OCaml's polymorphic variants](https://ocaml.org/manual/5.2/polyvariant.html)**. The two closest existing designs to inferred symbol sets.

### Pattern matching and exhaustiveness

- **[How to compile pattern matching](https://julesjacobs.com/notes/patternmatching/patternmatching.pdf)**, Jules Jacobs (2021). A design reference for a future general decision-tree matcher. The current first-version implementation uses interval/tag/string coverage and ordered lowering, without missing-case witnesses.
- **[pattern-matching-in-rust](https://github.com/yorickpeterse/pattern-matching-in-rust)**, Yorick Peterse.
  - Implementations of Jacobs' algorithm and of Sestoft's, with tests.
  - Jacobs' note says this version supports integer literals and ranges, guards, and exhaustiveness and redundancy checks.
  - Released under the Unlicense, so it can be translated freely.
- **[Gleam v0.33](https://gleam.run/news/v0.33-exhaustive-gleam/)**. Gleam replaced an incomplete exhaustiveness checker with Jacobs' algorithm, with help from Peterse's project.
- **[Warnings for pattern matching](https://resolve.cambridge.org/core/journals/journal-of-functional-programming/article/warnings-for-pattern-matching/3165B75113781E2431E3856972940347)**, Luc Maranget (Journal of Functional Programming, 2007). The algorithm behind OCaml's missing-case and unused-arm warnings.
- **[rustc pattern exhaustiveness checking](https://rustc-dev-guide.rust-lang.org/pat-exhaustive-checking.html)** and the [`usefulness` module documentation](https://doc.rust-lang.org/nightly/nightly-rustc/rustc_pattern_analysis/usefulness/index.html). How Rust adapts Maranget's algorithm, including integer ranges.

### Reference counting

- **[Perceus: Garbage Free Reference Counting with Reuse](https://www.microsoft.com/en-us/research/publication/perceus-garbage-free-reference-counting-with-reuse/)**, Reinking, Xie, de Moura, Leijen (PLDI 2021). How to insert reference count operations so that nothing is kept alive longer than needed.
- **[Koka](https://github.com/koka-lang/koka)**. The language Perceus was built for. It compiles to C with no garbage collector, and its C runtime, `kklib`, is a working example of object headers and count operations. Apache-2.0 licensed.
- **[Counting Immutable Beans](https://arxiv.org/abs/1908.05647)**, Ullrich and de Moura (IFL 2019), and the **[Lean reference on reference counting](https://lean-lang.org/doc/reference/4.26.0/Run-Time-Code/Reference-Counting/)**. Borrowed parameters that do not change counts, which is the model for parameters here.
- **[Lobster memory management](https://aardappel.github.io/lobster/memory_management.html)**.
  - Compile-time ownership analysis, with arguments borrowed by default. The author reports about 95% of count operations removed.
  - A report of leaked cycles at exit, which this plan copies for debug builds.
- **[Nim memory management](https://nim-lang.org/docs/mm.html)** and **[destructors and move semantics](https://nim-lang.org/docs/destructors.html)**. ARC and ORC, the model for adding the cycle collector later. Nim's compiler is also a large, MIT-licensed example of emitting C with `#line` directives.

### C output

- **[GCC integer overflow built-ins](https://gcc.gnu.org/onlinedocs/gcc/Integer-Overflow-Builtins.html)**. Overflow-checked arithmetic. GCC's C23 `<stdckdint.h>` is implemented on top of them.

### Error messages

- **[Compiler Errors for Humans](https://elm-lang.org/news/compiler-errors-for-humans)**, Evan Czaplicki (2015). Show the code as written, point at the problem, and suggest the fix. This is the style for this compiler's diagnostics.
