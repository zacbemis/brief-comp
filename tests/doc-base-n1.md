# Current raw-base inventory and independent examples (N1 scope)

`test_doc_base_n1.cmake` reads `docs/lang-ex-base.txt`, not `docs/v0/`. Its
**zero fences** are intentional: this is a 323-line mixed reference sheet, not
one complete source program. The entire file is hash-guarded and saved
byte-for-byte as **one unaccepted raw listing**. No function, usage line,
alternative or declaration is extracted, rewritten or completed.

The same test runs all **six complete examples** independently, with committed
output/status expectations. They are not executable fences of the raw sheet,
not supplied APIs, and not a claim that its User/Json/collection code works.

```sh
ctest --test-dir build -L doc-base --output-on-failure
# Select the independent examples and shared integrity guards:
ctest --test-dir build -L native-examples --output-on-failure
```

Normal/sanitized variants use the existing C program runner and the same
support gate as other native audits. The historical [base audit](doc-base.md)
stays retired. No v0 scaffold or syntax bridge returns.

## Whole raw-listing classification

These topics describe the one unaccepted listing, not native test counts or
extracted code regions:

| Topic | Why the raw sheet is not an accepted program |
|---|---|
| Primitive/binding notation | Forms such as bool x, bare let/var/const and a bare borrow marker are reference fragments. |
| Numeric/binding alternatives | Repeated bindings, intentional mismatches and missing context are interleaved; declared-then-assigned bindings still need N4. |
| Operators/control flow | Missing scalar names/functions, an intentional chained-comparison error and mixed inclusive/exclusive/collection loops. No supported first loop is extracted. |
| Literal/string notation | Array/vector construction and indexing are unavailable; interpolation is N5. |
| Animal/Color/ParseError/add/log | Some complete definitions occur amid fragments and usage. None is extracted to count as whole-source acceptance. |
| User/HasUser/Admin | Multiple file labels, traits/conformance, const, qualified names and unavailable Json APIs. No stand-ins or mock module lookup. |
| UserCollection | Vec, collection iteration/predicates, lambdas and Json APIs are unavailable. |
| Entry/handling/aliases | Missing User context, const alternatives, N2/N3 propagation/handling, clone and immutable-data policy. Sharing and clone are not equated. |

Parsing or rejecting this entire mixed sheet would not establish any of its
individual rules. The existing scoped syntax/types/functions/modules audits
supply their own precise native/prose evidence; they do not turn this raw
listing into passing coverage.

Each example's current whole-source hash is pinned for review. Its original
bytes remain the exact generated-source prefix; only expectation comments are
appended. No source line, name, payload, comment or newline is rewritten, and
no entry point or helper is inserted. Normal and sanitizer variants check all
six programs. File inventory equality prevents adding an uncovered example;
the test never regenerates expectations to hide a behavior change.

The examples exercise existing first-version scope, including owned recursive
values, permissions, constructors, conversions, matching and ordinary loops.
They deliberately work around unavailable collections, interpolation and module
APIs, as [their README](../examples/README.md) explains. Handling, optional and
entry behavior remains first-version until the reviewed N2/N3 changes.

## Integrity, artifacts and limits

The shared native harness now handles zero-fence chapters without inventing a
fence 1. Raw text is saved under `listed/` as txt, never a runner input. Example
cases have their own provenance/count, distinct from quoted fences and prose.
The compiler-free guards have two positive cases and 27 independent negatives,
covering mixed LF/CRLF/UTF-8 raw/example bytes, zero-fence completeness,
duplicate raw classifications, raw-as-native attempts, stale example hashes and
missing inventory/count coverage, alongside existing diagnostic/fix checks.

Generated raw copies, six program copies, provenance, inventory and runner logs
are under `build/tests/current-doc-base/` and `current-doc-base_sanitized/`.
Shared guards use `build/tests/doc-native-manifest-fixtures/`. Parser inventory
counts do not change: this remains one of its two unfenced listings, not a
promoted parser check. All five N1 audit entry points now exist, but the raw
sheet is still unaccepted natively and API limitations remain explicit.
The [final N1 review](next-version-n1-review.md) closes the milestone's scope,
not native acceptance of the raw listing or its unavailable APIs.
